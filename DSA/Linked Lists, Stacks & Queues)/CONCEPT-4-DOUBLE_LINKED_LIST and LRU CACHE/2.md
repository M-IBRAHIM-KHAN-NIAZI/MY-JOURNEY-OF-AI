Movement Logic Summary & Deep Dive (LRU Cache)

Step 1 (Setup & Initialization - The Container): Constructor (__init__) mein capacity, Hash Map (self.cache), aur dummy head & tail sentinels bante hain. self.head.next tail par aur self.tail.prev head par set ho jata hai taaki list ki boundaries lock rahein aur nodes aage-peechhe securely jud sakein.

Step 2 (The Disconnection Logic - _remove):

Yeh kahan aur kyun hota hai? Cache ke andar node chahe kahan bhi pada ho (list ke beech mein ya aage-peechhe), jab bhi hum usko access karte hain ya move karna chahte hain, toh sabse pehle use apni purani jagah se hatana parta hai.

Iske andar prev_node = node.prev aur next_node = node.next se aage-peechhe walon ko capture karte hain. Phir prev_node.next = next_node aur next_node.prev = prev_node karke target node ko list se mukammal taur par bypass (disconnect) kar dete hain taaki uska connection toot jaye aur woh isolated ho jaye.

Step 3 (The Connection Logic - _add_to_front):

Yeh kahan aur kyun hota hai? Jab kisi node ko remove kar diya jata hai ya koi bilkul naya node banta hai, toh use hamesha dummy head ke foran baad (Most Recent position par) laya jata hai.

Iske andar original_first = self.head.next se dummy head ke foran baad wali pehli node ko pakadte hain. Phir naye node ko head aur original_first ke darmiyan aapas ke pointers (self.head.next = node, node.prev = self.head, node.next = original_first, original_first.prev = node) adjust karke fit kar dete hain taaki woh list ka sabse naya (Most Recent) hissa ban jaye.

Step 4 (Why We Create a New Node & Save Key-Value?):

Yeh sabse zaroori sawal hai! Jab hum function ko call karte waqt put(key, value) likhte hain, toh woh sirf do aam numbers (raw values) hote hain.

Lekin hamari Doubly Linked List (DLL) aam numbers ko nahi samajh sakti—use aapas mein judne ke liye pointers (prev aur next) chahiye hote hain. Isliye hum new_node = Node(key, value) likh kar unhi kache numbers ko ek proper Node (dabba) mein pack karte hain.

Is naye node ko banane ke baad hum iske do kaam karte hain:

Hash Map mein self.cache[key] = new_node isliye save karte hain taaki agli baar jab koi get(key) kare, toh hum O(1) time mein direct is node ka address dhoond sakein.

Isko DLL ke front par laga dete hain taaki system ko yaad rahe ke yeh sabse recent use hua item hai.

Step 5 (The Search Logic - get): Jab hum get(key) call karte hain, toh if key in self.cache: se check hota hai ke key maujood hai ya nahi. Agar mil jaye, toh Hash Map se node nikaal kar self._remove(node) (purani jagah se hatana) aur self._add_to_front(node) (front par lana) chalate hain jisse node Most Recent ban jata hai, aur akhir mein node.val return ho jata hai. Agar key nahi milti, toh -1 return hota hai.

Step 6 (The Update & Eviction Logic - put): Jab hum put(key, value) call karte hain, toh do halat hoti hain:

Agar key pehle se maujood hai (if key in self.cache:): Toh node ko purani jagah se _remove karke value update karte hain aur _add_to_front se wapas front par laate hain.

Agar key nayi hai (else:): Toh pehle capacity check hoti hai (len(self.cache) >= self.capacity). Agar full ho, toh lru = self.tail.prev se sabse purana node hata kar Hash Map se delete (del self.cache[lru.key]) kar dete hain, aur phir naya Node(key, value) bana kar front par laga dete hain.

Step 7 (The Role & Difference of get and put):
Function definitions ke andar get aur put koi Python ke default built-in global functions nahi hain, balki yeh hamari apni custom methods hain jo LRU Cache class ke andar define ki gayi hain. Inke roles yeh hain:

get ka role: Yeh cache ke andar pehle se stored data ko search karne aur retrieve (bahar nikalne) ke liye use hota hai. Jab bhi yeh call hota hai, yeh value return karne ke sath-sath us item ko automatic Most Recent bhi bana deta hai.

put ka role: Yeh cache mein naya data insert karne ya purani value ko update karne ke liye use hota hai, aur capacity full hone par LRU eviction (tail se purani cheezon ko udaana) ko handle karta hai.
